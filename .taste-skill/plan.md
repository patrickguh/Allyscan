# Allyscan home page plan (Taste Skill 2.5.1)

Line 1: software (site-kind software, page type software)
Line 2: deal: hero triptych · palette blue-black-cornflower (developers read code in dark editors and
terminals; the sky-blue accent is the colour of a link and a focus ring, the two things an
accessibility tool talks about most) · type epilogue (Epilogue + JetBrains Mono) · radius sharp
(developer tool) · nav-centre (dealt nav-cards: no photographs, dealt to nav-centre) · footer-columns ·
close-word · rhythm dark-band (#aoda on .ground-inverse) · buttons tonal · mark: the client's own
logo (dealt "stack" replaced) · effect gradient-mesh in the one [data-visual] frame (#crawl) ·
moments word-highlight (#why), iris-opens (#aoda, from base).

Voice: technical-dry. Pairs: exact, not cold; sure, not loud. Person: "you" for what the visitor
gets, the product as the subject in feature lines. Sentences 8 to 16 words. Humour: none.
House words: page, issue, scan, criterion, crawl. Never: virtue words, a pun on the name.

Fact sheet (from the repo and README):
- What it is: an automated accessibility scanner for websites.
- For whom: Ontario site owners and developers who must meet AODA (WCAG 2.0 AA); recruiters
  reviewing a student portfolio project.
- Instead today: a browser extension that checks the one page that is open.
- True difference: follows same-site links (BFS, 20 pages max), scans each page in headless
  Chromium with axe-core, files issues under WCAG criteria.
- Numbers: 20 pages; WCAG 2.0 AA; O. Reg. 191/11 s. 14; 1 Jan 2014 (new sites, Level A);
  1 Jan 2021 (all sites, Level AA); 50+ employees; guest scans deleted after 1 hour; worker polls
  every 2 s; 3 attempts.
- Limit: automated checks find only part of WCAG; 20-page cap; a guest report shows once.
- Offer: free; no account needed; account keeps history. Main action: Scan a website.

Sections (1440x900):

7. #questions faq, answers open. 1 screen. calm.
8. footer.closing: close-word (Scan a website), footer-columns. 1 screen.
